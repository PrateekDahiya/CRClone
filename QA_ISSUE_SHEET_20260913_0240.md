#### ISSUE-501 [P0] - `MigrationRunner` reports success while creating nothing (001); crashes on 002 — live DB empty
- **Test:** Migrations up (001→005) against real MySQL 8.4 (Aiven, creds-provided env)
- **Expected:** All tables created; `schema_migrations` 001-005
- **Actual:** After run: `SHOW TABLES` = only `schema_migrations`; `schema_migrations`
  contains `001` marked applied with checksum — yet zero 001 tables exist. `002` aborts:
  `You have an error in your SQL syntax ... near '//' at line 7`. 003-005 never attempted.
  Transaction rollback on 002 worked (no partial state) — the one thing that behaved.
- **Root Cause (two bugs in `server/src/utils/MigrationRunner.ts`):**
  1. `applyMigration()` (`:99-105`) skips any chunk where `trimmed.startsWith('--')`.
     Every `CREATE TABLE` in `001_initial_schema.sql` is preceded by a `-- ... table`
     header line in the same chunk (e.g. `-- Players table\nCREATE TABLE ...`), so ALL
     DDL was silently skipped while the migration was recorded as applied.
  2. `splitStatements()` (`:145-150`) strips the delimiter with
     `current.slice(0, -delimiter.length)` on content ending `END//\n` — the trailing
     newline means it removes `/\n`, leaving a dangling `END/` → trigger DDL in
     `002_clan_system.sql:161-179` is corrupted. (Bonus: the first trigger chunk is also
     swallowed by bug 1 via its `-- Triggers...` header, so even a fixed splitter would
     create only the delete trigger.)
- **Reproduction:**
  1. Empty `crclone` schema on MySQL 8.x; run `MigrationRunner.runMigrations()`
  2. `SHOW TABLES` → only `schema_migrations`; `SELECT * FROM schema_migrations` → `001` present
  3. Re-run → `002` throws `near '//'`
- **Fix Prompt for Agent 5:**
  > In `server/src/utils/MigrationRunner.ts`: (1) rewrite `splitStatements()` (lines
  > 117-159) to strip `--` full-line comments (and `#` lines) BEFORE accumulating, so
  > comment headers can never cause a statement to be skipped or misclassified; operate on
  > the trimmed statement when removing the trailing delimiter (strip the delimiter from
  > `current.trim()` instead of raw-slicing, so trailing newlines can't leave a dangling
  > `/`); keep `DELIMITER //` handling for the trigger blocks in `002_clan_system.sql`.
  > (2) In `applyMigration()` (lines 90-115), replace the `startsWith('--')` skip with an
  > emptiness check after comment stripping, and add post-apply verification: after 001,
  > assert `players`/`battles` tables exist; throw (rolling back) if verification fails, so
  > silent no-ops are impossible. (3) Repair path: 001 is already recorded-with-checksum on
  > environments QA touched while creating nothing — add a `verifyRepair()` (or document the
  > exact `DELETE FROM schema_migrations WHERE version='001'` + re-run procedure) and note it
  > in `server/sql/migrations/README.md`. (4) Add `tests/integration/migrations.test.ts` that
  > unit-tests `splitStatements` output for 001 (statement count, none starting with `--`,
  > every `CREATE TABLE` present) and 002 (both triggers intact, no dangling `/`), WITHOUT
  > needing a live DB. Re-run the full 001-005 chain against the provided Aiven DB and report
  > final `SHOW TABLES` count. Keep `npm run test:unit test:integration` green.
